# 对照方案实施与验收的行动准则

1. 实施前逐条列出适用的行为和验收条件，标明入口、输入、输出、状态、失败和预算；对照现有调用者，确认哪些能力已经存在、哪些仍缺失。
2. 设计时先打通业务操作和控制状态的职责，再实现局部变更。检查同步、异步、配置工厂及下游实际入口，避免只修测试直接调用的内部方法。
3. 将条件组合起来验证：容量达到上限时出现遗漏、已有通过项遇到新错误、修复未改变、调用预算耗尽、并发和不同语言。验证失败时的数据保留和下一步行为。
4. 对每条验收条件建立可追溯证据。模型替身用于测试流程，真实模型与人工判断用于评估语义。未执行、失败、待核实、机械通过与语义通过分别报告。
5. 避免把 JSON 合法、调用成功、理由非空、测试总数或模型自己的 pass 当作正确性证明。避免只对已知例子调提示词，也不要把测试答案泄漏给模型。
6. 遇到错误放行、未预期停止或预算异常，保留原始请求、响应、输入、配置和版本；定位具体原因后修复并复验受影响路径。无变化的纠错不得记录为已修复；审核撤销原判应保存依据。
7. 完成前核对方案逐项状态与实际证据，明确未完成工作，不把阶段性结果描述成整体验收。遇到复验受阻应准确记录阻碍，继续可独立完成的工作。
