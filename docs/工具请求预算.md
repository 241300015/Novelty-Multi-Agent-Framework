# 工具请求预算

外部物理请求预算用于限制单个执行任务异常重复请求，不作为整个工作流共享的请求池。Harness 的轮数、工具调用次数、单工具次数及读取量限制仍是模型循环的主要边界。

## 隔离规则

- 每次工作流阶段执行（stage_id）有独立额度。研究任务通过工作流并发分发时，各任务有自己的 stage_id，所以互不占用预算。
- 首轮和补检的研究任务独立；首轮和后续 Validator 核验也独立。每次执行仍受对应限额约束，最大工作流轮数保持原配置。
- Reviewer 阶段内部并发的 point/card 评审通过显式任务上下文独立计数。同一任务标识在同一阶段内退出后重新进入不会重置额度。
- 同一个任务里的搜索、全文、重试等物理请求共享其额度；每次发送前原子预留，失败的请求也计数。不发网络请求的缓存命中不计数。
- 不在阶段中的独立工具调用落入该次运行的 unscoped 额度，仍有上限。
- 运行累计请求数只用于审计，不再作为跨阶段硬上限。RuntimeDebugConfig 禁用时原有行为不变：该记录器不执行此限制。

## 配置

`project.runtime_debug.max_physical_provider_requests` 默认仍为48，但语义改为每个阶段执行／并发任务的默认额度。旧 CLI 参数 `--max-physical-provider-requests 36` 现在表示每个执行任务默认36次，不再表示整个流程共36次。历史原始记录按旧语义解释，不改写。

可通过 profile 单独指定阶段额度，例如：

```json
{
  "project": {
    "runtime_debug": {
      "max_physical_provider_requests": 48,
      "provider_request_limits_by_stage": {
        "run_research_task": 48,
        "validate_evidence": 48,
        "review_evidence": 48
      }
    }
  }
}
```

阶段覆盖值适用于该阶段的每次执行、每个独立子任务，不是这些任务共享的总和。覆盖值必须为正整数，未配置阶段使用默认额度。模型调用预算 `max_model_calls` 是另一种限制，本次未改变其全运行语义。Agent 自身的工具调用次数限制仍由各 Agent 的 Harness 配置控制。

当前默认配置：全运行模型调用上限 210；每个研究任务物理请求 16、每轮 Validator 物理请求 40；研究 Harness 配置为 max_turns=48、max_total_tool_calls=30、database_search=4、reader=26。模型总调用额度按已记录单次实验峰值 105 的两倍设置；物理请求与工具调用分开计数。纠错仍消耗所属任务及全运行模型额度，没有新增独立纠错额度。研究 Harness 的运行时有效限制可能受内部轮数调整，以上为配置基础值。

## 追溯与验证

每次预留的 `provider_budget/*.json` 记录 `budget_scope=stage_invocation_task`、budget_id、阶段、任务标识、该额度内已用次数和限额。运行 manifest 和 summary 包含各预算用量；全局 dispatch_index 只用于唯一编号。

离线测试覆盖：研究额度耗尽后Validator仍可发送请求、下一轮新核验可继续执行、并发研究任务隔离、Reviewer并发子任务隔离与上下文复用不重置、同任务多线程竞争不超额、配置值校验，以及现代/旧配置构建路径。
