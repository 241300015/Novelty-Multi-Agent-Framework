## 实现

项目默认 Planner 配置开启 concept_review。两个工厂均读取该设置与操作 Prompt 的配置。沿用既有配置且未开启此项的调用者可以继续使用单次草稿协议。同步和异步工作流均通过 plan/aplan 获取 SearchPlan。

概念初审收到原查新点、任务和完整候选目录。复核分别判断词项可替代性、别名归属、原文支撑，返回每项的结论和遗漏问题。程序核对候选编号、既有编译器对语言及词项的限制以及分项判定。对遗漏单独补充，对未通过项最多进行三轮局部纠错。复核在新消息中执行。成功项冻结，空通过集停止，有通过项时将目录传给现有策略编译路径。

任务独立保存 input.json、events.jsonl、逐次概念调用、终态摘要和带 SHA-256 的索引。工作流成功时另存正式计划。请求取消、错误、部分完成和成功均有对应记录。运行目录为输出根目录下 planner-attempts/<attempt>/planner。read_attempt 核对绑定与文件摘要。单案例驱动按 A/B/C/D 构造单语或双语任务，可在生成后、初审前注入预先指定的遗漏或别名错配，保存修改前后版本。

离线回归耗时 56.579 秒。专项脚本覆盖正常规划、英中补译、并发任务隔离、三轮耗尽、部分放行、空集停止、响应契约纠错、产物摘要校验，以及下表中的语义路径。详细数据见 [结果摘要](results.json) 和 [专项 JUnit](focused.junit.xml)。

| 注入条件或判定 | 观察 |
|---|---|
| 初审指出概念遗漏 | 脚本补充并复核一次，正式计划纳入补充项 |
| 初审指出别名错配 | 脚本修正并复核一次，正式计划移除错误别名 |
| 初审给 pass，但别名分项为 false | 被送入修复，上述三类各用 5 次模型替身调用完成一次规划 |
| 连续三轮未修好 | 已通过概念保留，未解决项隔离；全体未通过时停止 |
| 全部分项误报通过 | 将“注意力层”作为错误别名仍被接纳，已复现一次 |

这些测试预先给定审核和修复响应。它们测量状态推进、错误隔离、修复后的再次复核及最终采纳，不能估计模型自行发现错误的概率。

## 真实实验状态

项目配置的 Qwen 服务 http://127.0.0.1:8000/v1/models 连接被拒绝。自然实验完成 0/30 个 task，受控注入完成 0/6 次，尚无人工语义签收，也无法给出相对历史模型的检出率或修复率变化。

恢复项目模型服务后，可先运行单次自然场景，检查输入和结果，再按方案逐次运行。每次使用独立尝试目录。

```sh
PYTHONPATH=.:backend/src python scripts/run_planner_concept_case.py \
  docs/experiments/20260915_224229/run/MF2033k6lC/novelty-points.json \
  --point NP-1 --scenario A --repeat 1 --output outputs/concept-acceptance
```

审核时应分别记录实际错误数、初审正确定位数、被正确修复数和错误放行数。由人工对照原查新点判定；仅有程序通过记录的案例保持待核实状态。
