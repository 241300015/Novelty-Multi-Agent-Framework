# 原方案指定条款验收协议

本轮只补齐原方案 §10.2、§10.3、§11.1—11.3 的实验和判定记录。生产代码冻结于 `80a40689`；不修复预算作用域、局部复核输入范围或模型语义问题。实验驱动、基准、配置和原始输入均记录摘要，批次中不修改 Planner、Prompt 或配置。

## 自然场景

固定原方案指定的两个 `NP-1`：GSAERU 和 Museformer，具体输入与核心覆盖清单见 [benchmark.json](benchmark.json)。每种场景独立重复三次：

| 场景 | 输入语言 | 任务语言 | 每次独立任务数 |
| --- | --- | --- | ---: |
| A | 仅中文 | 中文 | 1 |
| B | 仅中文 | 英文，需要补译对照 | 1 |
| C | 仅英文 | 中文，需要补译对照 | 1 |
| D | 中英文 | 中文、英文分别规划 | 2 |

总计24个场景、30个独立任务。每个任务启用 V2、自动任务判据和 Q/R 审核；独立运行上下文，最多32次实际模型调用，600秒超时。双语场景两个任务分别计预算。并发为2，不进行成功结果筛选，也不覆盖失败后重跑。

## 控制实验

目标为三次图摘要遗漏和三次细/粗粒度注意力别名错配。优先从自然实验的模型生成草稿中，按案例编号顺序选择满足条件的底稿：

- 遗漏：明确存在唯一图摘要概念，删除后没有其他同义词项继续表达该概念。
- 错配：细粒度注意力概念确有一个语义成立的别名，并有不同的粗粒度注意力目标。不能把原本错误的别名移动后当作新注入。
- 冻结生成草稿并明确记录生成回放；三个复核/纠错运行分别使用新的任务、上下文与预算。
- 在首次概念生成之后、首次复核之前修改草稿，不直接构造问题集。
- 审核输入不含注入说明、修改前草稿或预期答案。控制任务编号不透露错误类型。
- 条件不成立、尚未实际到达注入点、或审核前因上游故障停止，不能计作有效注入。

原始底稿、注入前后版本、字段位置、模型请求响应及失败记录均保留在忽略目录。若新草稿不能满足条件，应明确记录限制及后续准备方法，不通过伪造问题集补足数量。

实际准备调整：Museformer三份A场景生成草稿的别名均为空。因此，另以第二份完整生成草稿为底，让模型只给“细粒度注意力机制”增加合法别名“细粒度注意力”，程序确认其余内容未变；不计入自然样本。最初生成的另一份控制底稿只有两个机制、覆盖不足，保留准备记录但未用于注入。

六次全链路控制尝试分别保留。若它们在注入前被自动判据故障阻断，则追加单独标记的六次隔离实验：冻结GSAERU A1、Museformer A2在候选生成前已经形成的源输入判据，机械重绑定新任务的证据编号，冻结生成草稿；注入后的检测、纠错、新上下文复核和策略调用仍走当前实现并调用真实模型。源输入改变则拒绝回放。该组仅检验注入后的机制，不能抵扣自然矩阵中的上游失败，也不与全链路控制合并计算成功率。

## 独立语义判定

采用 [已确认通用规则](../semantic-baseline-rules.md)。Codex 读取原始输入、实际接受的概念/策略和运行轨迹，独立于运行时生成器与审核器做判定；无需逐篇人工审批。不能把运行时 `pass`、`completed` 或自动事实映射当作独立语义正确性证明。

每个任务分别记录：来源忠实性、词项/别名、核心覆盖、补译一致性、策略质量、流程与部分结果可用性。每项有理由和记录引用；无法判断标为待核实。失败发生在概念生成之前时，不能推算概念检出率和修复率。

| 分类 | 判定 |
| --- | --- |
| 完整达标 | 核心覆盖及六项独立检查通过，三个策略档位均合格 |
| 符合预期的部分结果 | 未解决问题明确隔离，实际放行内容正确且有意义，过程与预算检查通过 |
| 未达标 | 错误放行、遗漏未被登记、结果无实用意义、执行失败或已确认违反验收条件 |
| 待核实 | 必要的独立判断或证据不足，不计通过 |

双语场景只有两个任务均达标才计场景通过。自然实验、控制注入、环境配置失败及复验分别统计。条款补测完成与验收通过分别报告；已搁置的实现偏差不因测试通过而自动消失。
