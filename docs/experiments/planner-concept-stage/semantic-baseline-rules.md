# 已确认的通用语义验收规则

状态：本会话已确认以下八项规则。它们用于固定基准、自动审核和异常抽查，不要求每篇论文逐一人工签收，也不表示当前模型已通过语义验收。

| 规则 | 固定判据 |
| --- | --- |
| R1 GSAERU覆盖 | 概念集合应覆盖图快照序列、图摘要压缩、图自编码器与原图重构误差训练、循环神经网络学习时间依赖；允许等义措辞和合理组合，不限定概念数量 |
| R2 GSAERU替代 | 不同技术机制不能作为同组OR同义词，图摘要与循环神经网络不能互相替代 |
| R3 Museformer覆盖 | 保留细粒度注意力、粗粒度注意力及结合关系，并保留音乐结构／长序列建模语境 |
| R4 Museformer别名 | “细粒度机制”“粗粒度机制”缺少注意力限定，不直接认作等义别名；两种注意力机制也不能互为同义词 |
| R5 支撑与核心性 | 输入明确描述的机制不能因非主要创新而被判没有依据；证据ID合法不自动证明语义相关 |
| R6 修复身份 | 不可用另一概念替代原概念冒充修复；内容不变且原判撤销记invalid，不记真实修复 |
| R7 档位规则 | strict较完整覆盖技术组合；medium/broad可省略部分条件，但保留辨识机制；泛称本身不足以通过 |
| R8 LightGCN放宽 | medium/broad不强制AND“嵌入加权求和”，前提是剩余组合仍体现有辨识力的图传播与网络简化机制；不能仅因省略该项拒绝 |

## 程序如何为每个任务生成标准

1. 只读取原始查新点、技术特征与证据目录，提取主体—动作—对象和条件，区分去除、保留、使用、结合等关系。
2. 给事实发放F编号，区分辨识机制、支持细节及背景；再从这些事实生成各档最低要求。不同要求组为AND，每组允许的替代事实为OR。
3. 在概念生成前冻结判据及输入摘要。候选和纠错结果不能反向改写本次判据。
4. 概念复核给出与事实的对应关系，策略每个可命中分支都必须满足其档位要求。模型仍需审核事实映射、动作方向与检索语义是否正确。
5. 用固定正反例和异常抽查评估程序，而不是逐篇要求人工审批。无法确认的任务保留失败／部分状态，不自动当作验收通过。

固定基准的依据是项目中已有GSAERU、Museformer查新点及LightGCN输入；它们是评测案例，不是发给生成模型的答案。正常运行的判据完全由当前任务原始输入自动生成。

## 评估边界

来源片段和绑定由程序校验，事实抽取、重要性和事实映射仍涉及模型语义判断。因此，自动流程可以运行和纠错，但其准确性需通过基准评测验证，不能仅以模型自判pass证明。Planner首先对齐输入查新点，论文全文忠实性由上游抽取和相应评测负责。
