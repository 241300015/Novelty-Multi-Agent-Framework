# 单卡判断到点级综合的交接契约

当前协议为 `card_choices_v3`：点级 Reviewer 选择采用已有单卡判断，必要时定向复核，最后只撰写点级结论。
Harness 管理阶段、提供选项、复制判断并绑定证据。模型不重新填写单卡比较，也不修改原单卡记录。

## 数据边界

| 环节 | 数据与职责 |
| --- | --- |
| Reader / 单卡 Reviewer | 保持现有阅读和评审流程，留存完整证据账本、单卡比较及审计 |
| 默认点级输入 | `CardSummaryHandoff` 经选项映射提供单卡判断、未知项、局限和已选证据句柄；不展开原文 |
| 点级选择 | Harness 提供“采用剩余判断”“定向复核某卡某特征”“放弃某张卡” |
| 定向复核后 | 选择保留原判断或放弃整张卡；不能编辑特征关系、理由或证据 |
| 最终模型输出 | 仅 `status / verdict / verdict_reason / confidence / supplement_request`；status 必须符合此前菜单选择的结果类型 |
| 最终程序输出 | 结论加上所有已采用卡片的完整比较、相关文献条目和原证据关联 |

内部 `card_judgment_v1` 和历史持久化单卡格式保持兼容。新增 `ReviewerSummaryNarrative` 只约束模型输出，
既有 `ReviewerSummaryDraft` 用于程序装配。`NoveltyPointReview.summary_harness_state` 默认空字典，旧报告无需迁移。
`core/reviewer_choices.py` 不再提供允许模型重填 `revised_comparisons / additional_works` 的点级编译入口。

## 阶段与放弃规则

`ReviewerSummaryPolicy` 接入现有 `ToolCallHarness`，每个调用创建独立菜单及版本。菜单阶段严格输出一个
`option_id`；未选完不能提前提交结论。最终阶段和格式修复都使用同一严格的结论 schema，禁止附带单卡字段。

默认一次选择采用全部剩余判断，然后一次调用撰写结论。模型可先选择复核或放弃某张卡，再采用剩余判断。
放弃以整张卡为单位，仅对本次汇总有效：该卡比较和相关文献条目均不进入最终结构化判断；
原单卡结果、留存证据和 checkpoint 不删除、不改写。另一张卡即使对应同一 Work，也可继续采用。
最终及失败结果的 `summary_harness_state` 记录放弃、采用和阶段选择，避免失败后丢失已发生的控制动作。

如果全部卡片被放弃，只提供证据不足收尾。剩余卡片对同一 Work/feature 的关系、依据类型或来源归属冲突时，
不能直接采用它们输出裁定：可以复核、放弃某张卡，或保留冲突并以证据不足收尾。
程序只去掉完全相同的结构化重复项，不合并不同理由或引用，不替模型选择更“正确”的判断。
不同条目仍受既有 `not_novel` 完整单篇覆盖校验约束。

## 定向复核与证据

复核目标由 Harness 从该卡现有特征比较构造，固定 Card、Work、feature 和该比较的全部 evidence_refs。
模型只选择菜单，不填写目标身份或工具参数。内部 `reviewer_recheck` 返回这些已留存证据的完整原文和哈希；
模型看到的是当前调用的短选项，数据面保留真实 ID。不会调用外部 Reader、重新获取论文或重评整张卡。
单卡 Reader 工具的回读能力保持不变。

没有选中证据的 unknown 项不提供原文复核选项；模型仍可放弃该卡。超出剩余字符预算的目标不出现在菜单中，
不截断后假装展示了完整证据。复核失败明确回传失败，由模型决定是否继续信任原判断或放弃该卡，失败不算核验成功。
这里没有实现新材料读取、通用上下文压缩或单卡自动重评。

Harness 复制后继续验证 Card/Work/point/feature 与选中证据的关联。点级比较必须与已采用卡片中的某条记录完全一致。
`summary_result.comparison_origins` 的 `assembly=harness_card_selection` 表示程序复制，不再把模型碰巧抄对视作程序承接。
身份与来源合法不证明单卡语义正确；点级自由文本也仍需语义验收。

## 预算、恢复与报告

- `summary_max_calls=6` 包含菜单、结论和一次格式修复；正常采用需要两次模型调用。
- 一次复核、决定保留或放弃、采用剩余判断、撰写结论通常共四次调用。
- `summary_max_rechecks=2`、`summary_max_recheck_chars=32000` 和 `summary_timeout_seconds=180` 继续独立控制点级预算。
- 预算不够不会跳过待完成菜单强行生成裁定；返回失败并记录当前阶段。

旧单卡事实可用新协议重新生成点级总结，通常无需重新阅读。仅重渲染旧报告不会执行新菜单或改变原裁定。
若单卡判断本身缺少可靠依据，仍需补评。提示版本变更会改变 checkpoint 配置指纹，不能绕过旧 checkpoint
的冻结检查；应保留旧实验，从原单卡事实建立新 checkpoint。

点级结果用于完整和简洁报告；结构校验不能证明 unknown 与最终自由叙述在科学含义上一致，仍需语义验收。

### 报告采用边界修复（2026-11-15，issue #35）

后续审查发现：点级虽已放弃某卡，Coordinator 分组和简洁报告仍可能重新使用其判断。
当前下游修复将 `summary_harness_state` 作为 Reviewer 权威字段复制至报告，Gate B 检查其一致性，
报告组装及兼容绑定均拒绝在支持/反对分组中重新引用未采用卡。
Coordinator 输入只提供本次可用卡和相应核验证据；持久化单卡及完整读取账本不修改。

简洁版保留文献编号并明确标记未采用，不把原单卡比较重新并入有效评判；默认版的单卡表
可显示原判断供审计，但标记“本次点级未采用”，最终依据区不展开弃用卡的原文。
总结失败时仍保留未被放弃的部分成果；同一文献的历史多卡数据按卡片身份处理，不因弃用一张而误删另一张。

旧报告缺少该字段时默认保持兼容，不把缺字段解释为全部弃用。若同次运行的持久化点评审包含
采用状态，重渲染可使用该状态标记并过滤单卡详情；历史 summary 自由文本、支持/反对分组
需要重新生成并通过绑定与 Gate B，不能靠重渲染宣称已全部修正。Reviewer 提示和裁定规则未修改。

### 下游分池与快照（2026-11-16）

上述 2026-11-15 行为是历史修复记录。新流程进一步把主动弃用单独持久化，Gate A 只审计候选池，
明确输出 `report_disposition`；Gate A 失败不再借缺失状态进入旧协议兼容。原始单卡/汇总独立保存，
报告统一组装 `sources`，Renderer 不再回读原始单卡或叠加局部成果字段。
Gate B 审计独立落盘且保持非阻断；历史目录不迁移。完整责任表见 [数据流第 7 节](data_flow.md#7-reviewer-下游与落盘目录2026-11-16-收敛实现)。


## 证据身份由 Harness 负责

每次调用有独立注册表，只有获准 Card 的原始证据、本次成功读取证据或点级交接选中证据才能注册。模型使用短选项，程序回填真实 ID；过期、跨调用、跨身份类型的选项精确拒绝，不做模糊纠正。

单卡读取后扩充证据选项；最终草稿与格式修复使用相同的最新 schema 和注册表。审计保存 choice_bindings，供离线追溯，不把该映射交给模型。

点级先通过 option_id 菜单选择结果类型，再生成 ReviewerSummaryNarrative；最终 status 及 verdict 的允许范围绑定此前选择，格式修复不能改变已选结果类型，也不能新增/改写单卡判断。证据不足是合法完成，不等于技术失败。

## 验证与边界

`tests/test_reviewer_summary_policy.py` 检查完整复制、默认不展开长原文、定向复核、整卡弃用/全部弃用、冲突、预算和调用隔离；`test_reviewer_summary_outcome_contract.py` 检查结果选择；`test_review_pools.py` 检查 Gate A 与下游快照。checkpoint、严格输出、工作流和报告测试覆盖相应边界。

这些是程序契约验证。真实模型是否选择合理复核、是否正确理解原文、是否给出科学上成立的结论，需要独立评估。实验原始记录不随本功能说明提交。
