# Reader 上下文累积处理方案（待实施）

日期：2026-11-16，Asia/Shanghai。本轮只提供方案，不修改 Reader、Harness 历史策略或模型容量配置。

## 已确认的问题

已有本地真实运行中，Researcher 的一个补检任务读了 8 份摘要（12,101 字符），随后连续读同一篇综述的 5 段正文（每段 16,000 字符，共 80,000 字符）。各段均成功读取，47 条消息继续保留全部观察。

最后的 `llm_0088` 输入 30,484 token，另预留输出 4,096 token，总计 34,580，超过模型窗口 32,768，被服务端拒绝。上一调用输入为 26,411 token。失败发生在决定下一步时，不是 Reader 文件读取失败，也不是 Reviewer 调用失败。

已有 `backend/env/context_admission.py` 支持按最终请求精确计数并拒绝超限，不修改输入；本轮该调用没有启用容量准入。`runtime_state_projection` 只补充运行状态，仍保留全部历史消息，不能作为已实现的上下文压缩方案。

## 推荐设计

把材料完整保存、每次模型可见范围、最终裁定证据分别管理。完整材料与读取回执始终保留；模型不必在每次选择菜单时重新接收全部原文。减少每次重复输入会改变模型可见上下文，必须以显式版本和测试记录，不能声称与完整历史完全等价。

### 1. 容量准入与阶段预算

- 复用现有 ContextAdmission，按实际服务端 tokenizer/chat template 对最终请求计数，包含系统提示、工具 schema、消息、输出预留；计数不可得时明确暂停，不用字符数冒充 token 数。
- 分开配置菜单选择、段落分析、证据成卡的输出预算。只输出 option_id 的菜单选择不应沿用 4,096 token 的成卡预算；合理下调输出预留不改变读取内容，但只能缓解本次触发点，不能解决无限历史增长。
- 为段落分析结果和交接预留空间，提前触发会话交接；不能等请求已超限后再要求原会话生成总结。
- 容量拒绝路由到上下文交接或可恢复暂停，不重新搜索、不偷偷重试同一超限请求，也不转换成“文献不存在”。

### 2. 阅读与分析以段为单位，原文不截断

每次 Reader 返回的段落原文完整持久化，保留 namespace、Work、artifact、artifact_hash、read_id、字符区间和文本 hash。所有原始模型请求、响应和操作日志照常落盘。

段落分析在独立、有容量上限的调用中完成。输入是研究问题、当前任务、该段完整文本、必要的相邻段及尚未解决的问题；输出是带出处的段落记录，至少区分作者方法、相关工作、背景和无法确认的信息，保留候选证据的逐字引文与坐标。一次分析失败保留原段并标记未分析，不把读取成功等同于分析完成。

如果某段自身装不进窗口，按实际 token 容量重新分段并覆盖原完整区间，不删除尾部或更改已保存回执；边界上下文可重叠，必须能核验全区间覆盖且无遗漏。

### 3. 显式 checkpoint 交接，避免滚动累积全部原文

在容量阈值到达前保存完整任务 checkpoint，启动新模型会话。交接输入包含当前任务、已用来源、检索与阅读游标、未解决问题、带原文锚点的段落记录索引以及剩余预算，而不是复制所有原始读取消息。

建议放在现有论文工作区下的新版本目录：

```text
researcher-checkpoints/<run_id>/<point_id>/<task_id>/
  checkpoint.json          # 当前阶段、游标、剩余预算、材料/记录版本绑定
  segment-notes.json       # 逐段记录、引文锚点、分析状态；不冒充原始证据
  sessions/<session_id>/   # 每次交接的输入范围、原因、请求 hash 和审计记录
```

以上为建议布局，尚未创建生产目录或迁移历史数据。TaskResearcherWorkflow 负责交接与恢复；Reader/ReferenceStore 继续负责不可变原材料和读取回执；Harness 负责阶段、预算和发送前容量检查。旧任务没有 checkpoint 时继续走旧协议，不能猜测或伪造历史分析状态。

### 4. 成卡必须回到原文，不把摘要升级为证据

段落记录只是导航材料，有漏项或失真风险。最终成卡输入使用任务所需的段落记录，并按锚点调取对应原文、上下文以及互相矛盾的材料。EvidenceBuilder 继续验证逐字引文、Work、artifact 和读区间；Reviewer 的裁定职责不变。

如果段落记录索引自身也过大，可建立分层索引并分批处理，但底层原文、所有段落记录及状态仍可寻址。任何未调取材料不能被当作已综合考虑。证据跨段且当前容量仍不足时，保留未完成状态和待处理范围，不强行生成科学判断。

如果一个必要的最终比较本身无法放入窗口，应显式报告容量限制，或使用经验证的分阶段比较/更大窗口模型；有限窗口不可能无损地同时容纳无限全文。

## 实施顺序与验收

1. 先用本次失败请求和长文离线材料验证容量准入、阶段预算和交接触发。准入本身只负责防止非法发送，不能声称已解决长文分析。
2. 再实现段落记录与可恢复交接，保持原材料和旧行为作为对照；不能只打开现有 runtime_state_projection 后宣称完成。
3. 最后运行同一冻结材料的真实模型对照，分别评估执行稳定性、实际阅读/分析覆盖、证据准确性、语义质量、调用及 token 成本。额外段落分析会增加调用次数；不预先承诺总成本下降或质量等价。

必须覆盖：跨 32K 长文连续阅读、跨段证据和反例、段落记录遗漏、损坏 hash、计数服务不可用、交接前后中断恢复、总预算耗尽、最终综合仍装不下。

验收要求：原始文本/hash 不变；完整读取与已分析范围分别可追溯；交接后不漏段、不重复扣账；新增引文可定位原文；不将段落笔记冒充独立证据；所有发出的请求均在容量内；异常保留明确可恢复状态。只通过运行检查不足以证明科学质量不退化。
