# S0 动作协议

S0 先检查主体、动作、对象、完整描述、证据 ID 和任务绑定。动作保存在 `action` 中，程序为登记词计算 `action_code`，并用 `action_status` 记录进 S1 前的处理结果。动作表仅匹配大小写和空白差异。未知表达不会被替换成近义词，单次复核成功也不会自动入表。

| 新登记动作 | 正例 | 保留的语义限定 |
| --- | --- | --- |
| `models` | 将动态图建模为快照序列 | 保留建模对象和产出的表达形式，区分“执行建模”和“具有建模能力” |
| `learns` | 通过循环网络学习时间依赖 | 保留所学对象和实现手段 |
| `trains` | 利用原图重构误差训练节点表征 | 保留训练对象、目标和误差信号 |
| `compresses` | 用图摘要压缩原图 | 保留压缩对象和方法 |
| `inputs` | 将压缩图送入图自编码器 | 区分被送入的数据和接收模块，禁止颠倒方向 |

登记表示动作表承认这种表达。证据、对象、方向和条件仍由事实提取、现有概念审核与策略审核检查。S1 依据事实的 `kind` 和 `importance` 判断定义性机制。旧输出缺少 `kind` 时使用动作表对应的默认分类。只报告性能结果的事实属于效果，描述中间表示如何生成的事实可以属于技术机制。

若提取同时输出 `kind=outcome` 和 `importance=outcome`，程序将后者订正为 `context` 并留下记录，再执行完整校验。结果、目标和背景事实即使被标为 `defining`，也按上下文交给后续环节。

1. 未知动作通过结构与证据校验后，按任务批量发送独立复核。复核通过须确认原文支持、关系方向和事实限定，并给出分类及理由。
2. 对可修事实发出一次纠正请求，按原事实 ID 处理。第二次复核只检查发生变化的事实，使用修正前后的事实与原文。
3. 两次复核共享 S0 的三次输出契约修复额度，运行总调用预算优先。复核未通过的事实记录排除原因。
4. 关键事实未通过或没有可用定义性机制时，停在 S0。能隔离的可选事实先排除，其余事实保留原 ID 进入 S1。任务若产出计划，审计和最终报告标为部分完成。

## 2026-11-18 定点验证

实验分支为 `1st-stage-t1-experiment`，历史对照来自 [原方案验收补测](acceptance-20261116/report.md)。本次真实测试运行至 S1 完成。样本来自原批次中已出现动作枚举错误的任务。

| 同一输入 | 历史结果 | 当前 Qwen 结果 |
| --- | --- | --- |
| GSAERU A-3（中文查新点、中文任务） | S0 枚举错误，4 次事实请求后停止 | 1 次提取和 1 次判据生成，S1 完成 |
| GSAERU C-1（英文查新点、中文任务） | S0 枚举错误，4 次事实请求后停止 | 1 次提取和 1 次判据生成，S1 完成。程序订正了效果事实的重要性字段 |
| Museformer C-1（英文查新点、中文任务） | S0 枚举错误，4 次事实请求后停止 | 1 次提取、1 次动作复核、1 次判据生成，S1 完成。保留 `compares to`，按效果处理 |

额外回放 Museformer C-1 的历史首次事实响应，由 Qwen 完成动作复核与 S1 判据生成。历史 `compared to` 经复核后仅对本次任务生效，保留为效果事实。该样本单列为回放加真实复核，事实提取未重新调用。

同一批历史首次事实输出中，22 份会被旧动作枚举拒绝。新协议在复核前的离线结果为 10 份通过结构、证据和动作登记检查，9 份进入待复核，3 份仍有结构或证据错误。这个分布衡量协议入口行为。全仓非 live 回归 2,124 通过、3 跳过、0 失败。定点复验支持入口恢复，之后的概念质量、纠错与三档策略仍以整批验收为准。
