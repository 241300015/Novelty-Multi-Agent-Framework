# 作者姓名格式适配范围

元数据检索和核验支持 `Charlotte E. Lee` 与 `Lee, Charlotte E.` 两种写法。逗号明确标识姓在前；无逗号时按名在前、最后一个空格分隔的词为姓生成查询备选和比较键。比较键保留姓、名边界，避免将 `Lee, Charlotte E.` 和 `E. Lee, Charlotte` 视为相同姓名；超过一个逗号或逗号一侧为空的输入仅按原文本比较。作者列表仍逐位比较，不改变作者顺序，不修改原始记录。DataCite 查询为每位作者使用两种形式的 OR；Crossref 查询使用名在前形式。是否能够召回仍取决于来源的索引、其他查询条件及候选页限制。

DataCite 的 [Creator 规范](https://datacite-metadata-schema.readthedocs.io/en/4.7/properties/creator/) 建议个人作者使用“姓, 名”，并提供可选的姓名类型、名、姓等字段；作者也可能是机构。[DataCite 查询文档](https://support.datacite.org/docs/queries)支持 `creators.name`、引号及 `OR`。当前模型仅传递作者字符串，未将这些结构化姓名字段用于核验，因此不能据此可靠识别机构或多词姓。[真实 API 样本实验](experiments/20261102_author_name_acceptance/README.md)已记录特定文献的召回结果，不代表普遍召回效果。

尚未覆盖或可靠适配：无逗号的姓在前、复姓或姓氏前缀的自动识别、缩写与全名互换、标点或重音差异、音译及不同文字之间转换、后缀和头衔、机构作者、作者缺失或增减以及作者顺序变化。格式转换不证明身份，尤其不能从字符串可靠识别个人姓名与机构名称；上述情况需要后续结合结构化姓名字段和实际样例处理。

风险：机构名 `World Health Organization` 会被当作名为 `World Health`、姓为 `Organization` 的个人姓名，因而与 `Organization, World Health` 错误等同；这可能隐藏来源冲突或使作者核验通过。多词姓如 `Ana de la Cruz` 与 `de la Cruz, Ana` 则可能无法匹配。保留 DataCite 的 `nameType`、`givenName` 和 `familyName` 并传播到比较层需要另行扩展数据模型，当前未实现。

## 审查记录：暂不修复

- **来源作者条目缺名**：DataCite 和 Crossref 解析器会跳过没有可用姓名的作者条目，后续核验无法判断作者列表是否因此不完整。离线构造的来源记录中，作者为 `Alice` 加一个缺名条目时，解析后只剩 `Alice`，与本地单作者匹配并通过。这是受控复现；本轮真实实验未观察到该问题。
- **机构名称歧义**：当前字符串比较无法区分机构与个人，如上述机构名示例可能被误等同。这是代码路径和构造示例揭示的风险；本轮真实实验未观察到由此造成的冲突或错误放行。

两项目前仅记录，不修改解析器、姓名比较或 Validator 核验规则。
