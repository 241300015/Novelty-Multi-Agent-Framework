# 作者姓名转码验收：DataCite 与 Validator → Reviewer

> 本摘要随 Validator 任务文档保存；本轮实验原始记录、输入材料和运行产物暂留工作区，不纳入本次提交。文中指向这些材料的链接在未取得本地记录的检出中不可用。

日期：2026-11-02（北京时间）。本轮只验收真实 DataCite 查询、Validator 核验及其与真实本地 Reviewer 的分阶段衔接，不运行 Coordinator、报告合成或补检。原始姓名与转码后查询分别执行一次；题录、查询、响应、匹配与运行结果均保存在本目录。实验样本及预期在首次正式查询前写入 `cases.json`，其 SHA-256 保存于 `datacite_queries.json`。

## 样本和方法

- 历史五篇：ScaGNN、BandPC、SDT-GNN、ABC、2PS。它们的输入是历史阶段保存的本地作者与年份；已记录的 DOI 仅作为目标身份和精确对照，不倒灌历史无 DOI 查询。
- 独立五篇：Transformer、ResNet、BERT、Adam、VAE。选择以官方 arXiv 页面所列完整作者、标题、首次提交年份和 arXiv DOI 为依据；来源见 `cases.json`。五篇均为 arXiv 文献，不是随机样本，也不能代表 DataCite 的整体覆盖。
- 实际 DataCite Provider 分别发出原始作者条件、当前转码条件、精确 DOI 查询，每篇三次。原始条件通过实验进程中对姓名版本函数的临时覆盖重现转码前表达；没有更改生产代码。生产 Provider 的请求限时 8 秒、IPv4、无自动重试。`datacite_queries.json` 保存每次请求参数、状态和完整来源响应；身份以预先登记 DOI 校对。
- 历史真实材料：从原阶段输入和 ReferenceStore 直接运行生产 Validator；批次各保留全部卡，以免筛选通过卡。单 DataCite 与历史回放脚本使用的三来源（DOI.org、Crossref、DataCite）分别运行。
- 独立五篇正例、十个错误作者对照：用来源真实标题构造仅含题名的受控本地材料，回放本次保存的真实 DataCite 响应，执行生产 Validator；它不是实时请求内联执行，也不是有科学内容的研究证据。负例只把本地第一作者换成 `Synthetic Wrong Author`，使用真实精确 DOI 响应保证 Validator 面对实际题录，而不是依靠检索未命中。详见 `controlled_validator_results.json` 及 `controlled/` 中的引用材料。仅此明显错误姓名不能验证细微姓名差异或机构作者问题。
- 下游只对真实历史材料，将各批三来源 Validator 实际放行的卡通过原 Reviewer 回放脚本的隔离副本传入 `_review_evidence`，引用材料逐批复制；独立题名卡不进入 Reviewer。隔离副本仅调整输入输出、单来源选择和拒卡传递，没有创建连续工作流。各批输出和真实调用轨迹保存在对应 `reviewer_*` 目录。结果是分阶段测试，不是连续工作流端到端运行。

## 结果

| 组别 | 原始姓名查到预定 DOI | 转码姓名查到预定 DOI | 精确 DOI 查到预定 DOI |
|---|---:|---:|---:|
| 历史五篇 | 0/5 | 5/5 | 5/5 |
| 独立五篇 | 0/5 | 5/5 | 5/5 |

转码查询十次均返回一个目标记录且未截断，按现有身份比较均通过；原始姓名查询均为 HTTP 200 的 `not_found`。这是本次特定时点的对照，不保证未来查询结果或其他来源的覆盖。

五张历史目标卡在实际 DataCite 单来源 Validator 中均通过；五张独立文献受控正例使用已保存的真实响应回放，也均通过。十个受控错误作者对照均被 Validator 因作者不一致拒绝，未观察到错误放行；它们只使用单来源，不能证明多来源没有错误合并。多来源真实历史回放中的五张重点卡对应目标 DOI，未观察到明显跨篇错误合并；这不是对所有作者和冲突类型的覆盖。

历史批次含额外非目标卡：DataCite 单来源 09-17 为 4/5 通过、09-30 为 2/3 通过；三来源分别为 5/5 和 2/3。单 DataCite 拒绝的 Window 和 EvoFormer 卡均涉及本地会议 DOI 与返回 arXiv DOI 不同；Window 由另外来源的本地 DOI 题录支持而在三来源下通过。不同 DOI 的版本未自动视作相同。多来源结果可能包含被否决候选的失败事件；事件条数不能当作拒卡数。错误作者对照的审计可同时含 no_match 和 identity_mismatch，必须结合实际返回记录及作者差异解释。

## 运行记录和限制

初次探测的沙箱代理与 DNS 不可用，隔离环境外 DataCite 与本地模型端口可达。正式查询第一次启动因 Python 模块路径配置错误在发出任何请求前退出；修正后运行。Reviewer 首次因子进程缺少 `LOCAL_VLLM_API_KEY` 占位值而未能调用模型，记录在 `reviewer_0917/` 和 `reviewer_0930/`；随后对该技术故障以本地占位值重试，保留两个独立结果。重试开始前有一次 Python 可执行路径输入错误，未启动脚本。两批重试各自采用单并发配置，后期运行有重叠。

机构名与个人名混淆仍可能错误匹配；多词姓、缩写、不同拼写和版本等未被本轮覆盖。独立样本全部来自 arXiv、真实作者写法均为姓前逗号形式，受控负例全部使用明显的错误作者。实验不推断总体准确率或普遍召回效果，也不将 Reviewer 的语义判断当作人工真值。

## 真实 Reviewer 衔接

首次两批共 7 次调用均在启动模型请求前因缺少本地占位凭据失败。重试仅在子进程设置占位值、关闭代理并继续限制本机地址；两个批次使用各自隔离输出目录，不覆盖首次记录。

| 批次 | Validator 实际放行并交给 Reviewer 的卡 | 重试模型调用 | 查新点评审结果 |
|---|---:|---:|---|
| 09-17 | 5/5 | 7 | NP-1 `technical_error`；NP-2、NP-3 返回 `reviewed` |
| 09-30 | 2/3；另一张拒绝 | 3 | NP-1、NP-3 无可用材料；NP-2 `semantic_evidence`，未完成裁定 |

09-17 的卡片评审中，至少两次因 `unread or empty read_id` 无法完成。两项 `reviewed` 是模型和工作流输出状态，不等于结论已获证实。实查其引用时，NP-2 将领导—工作者模式标为引用证据的直接陈述，但其引用的 SDT-GNN 摘录只描述流式边输入及图划分，没有该模式；NP-3 以 WStream 摘录直接标记“未使用最小堆”，而摘录没有给出这一否定事实。这些是证据支持不足的具体发现，不推断原文全文一定支持或否定相应结论。Reviewer 行为及语义质量因此没有全面通过，尽管已核对实际放行卡列表传入 Reviewer。

`reviewer_0917_retry/review_result.json` 与 `reviewer_0930_retry/review_result.json` 保存结构化结果；同目录 `reviewer_events`、`llm_calls` 与各批原材料副本可用于逐次追踪。脚本沿用原运行 ID `review-existing-0917`，即使在 09-30 隔离目录下也是如此；以目录名区分批次。运行重放不声称两批为同一次研究，也未触发自动补检。

重试的 7+3 次模型传输均有成功记录；09-17 两个 `reviewed` 结果仍分别带有 `review.missing_features` 和 `model.output_reference` 执行问题，不应只凭状态字段判定完整、可靠。独立只读复核确认各批 Validator 放行 ID 与 Reviewer 接收 ID 一致、各接收卡均有 Reviewer 开始事件，拒卡没有传入该列表。
