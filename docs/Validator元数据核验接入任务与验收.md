## 本轮完成与验收结论

### 已完成工作

- 正常工作流入口可按后端配置创建并持有元数据检索服务，默认 Validator 使用该服务；配置关闭或初始化失败时记录未执行外部核验的原因，工作流持有的服务在结束时关闭。见[工作流实现](../backend/src/novelty_agent_framework/workflows/novelty.py)和 [Validator](../backend/src/novelty_agent_framework/agents/evidence_validator.py)。
- 元数据服务分别查询来源并组装身份候选，记录来源、字段冲突及故障；Validator 比较候选并保留逐卡查询和放行／拒绝审计。候选采用 OR：有匹配候选时其他候选的不一致仍保留；外部题录不能绕过本地材料、引文及位置检查。见[元数据服务](../backend/src/novelty_agent_framework/tools/metadata_retrieval.py)和[身份核验](../backend/src/novelty_agent_framework/core/metadata_verification.py)。
- 姓名格式适配支持 `Charlotte E. Lee` 与 `Lee, Charlotte E.` 两种形式，作者列表仍按位置比较；DataCite 题录查询使用姓名形式备选，Crossref 查询使用名在前形式。比较键保留明确的姓、名边界。适配范围见[作者姓名格式适配](作者姓名格式适配.md)。

### 已取得的验收证据

- **受控材料与正常入口**：以四篇公开文献的短摘录、受控来源响应及生产工作流入口测试，55 个预设场景均符合预期；其中身份核对 39 例为 TP=24、FP=0、TN=15、FN=0。标签未经人类审阅；实验未调用真实网络或模型，使用替身执行部分组件，并替换异步线程桥接，不能作为真实端到端或异步调度验收。完整方法和分类见[受控实验](experiments/20261101_validator_metadata_real_cases/README.md)。
- **真实 DataCite 姓名查询**：历史五篇及独立五篇在当次真实查询中，原始作者写法命中目标 DOI 为 0/10，转码写法为 10/10。历史五张目标卡在实时 DataCite 单来源 Validator 核验中 5/5 通过；独立五篇使用本次真实响应回放和受控题名材料的 Validator 正例为 5/5 通过。样本均为 arXiv 文献，非随机，不代表总体召回率。见[姓名适配验收](experiments/20261102_author_name_acceptance/README.md)。
- **实时错误作者对照**：对五张真实历史证据卡分别构造正确作者与错误首作者对照，正反例均加入已核对的 arXiv DOI 后实时查询 DataCite；正例 5/5 接受，负例 5/5 拒绝，均实际取得目标题录。该组准确率为 10/10，误拒率 0/5，误放行率 0/5；这些是五篇文献上人为构造明显错误作者的样本结果，不是总体准确率或误放行率。见[实时对照](experiments/20261102_live_validator_wrong_author/README.md)。
- **Validator 到 Reviewer 的衔接**：两批历史材料在多来源 Validator 实际放行的卡分别为 5 张和 2 张，其 ID 与 Reviewer 接收列表一致；拒卡未进入该列表。这是复用现有脚本的分阶段回放，不是从上游开始的连续端到端验收。按用户确认，本轮不验收 Reviewer 内容、Coordinator 或最终报告。
- **代码及离线测试复核**：提交前在隔离环境外运行 Validator、元数据检索、DOI Provider 和正常工作流入口测试，以及完整性检查、工作流和故障追踪测试，均通过；其中包括此前因隔离环境线程调度问题未完成的异步测试。审查另发现下面记录的边界，未据此扩大本轮实现范围。

### 未覆盖事项与保留风险

- 复姓和姓氏前缀自动识别、无逗号姓在前、缩写与全名、音译、标点或重音差异、后缀、作者增减与顺序变化未可靠适配。机构作者可能被误当作个人姓名；来源中缺名的作者条目可能被解析器跳过，令作者列表看似完整。后两项已用构造示例或代码路径确认风险，本轮真实实验未观察到相应错误；按用户决定只记录、不修复。详见[作者姓名格式适配](作者姓名格式适配.md)。
- 存在共同 DOI 时，作者字段缺失不一定阻止身份核验通过；身份通过不等于作者字段已完成比对。不同出版版本可能有不同 DOI，不应仅按标题相似就视为同一记录；DataCite 未命中也不证明文献不存在。
- 隔离环境中独立的 `asyncio.to_thread` 最小示例曾超时，根因未确定；此前受控实验替换线程桥接，不能以该实验证明异步调度。提交前相关异步测试在隔离环境外通过，但这不证明隔离环境问题已解决，也不代表所有并发场景均已验收。
- 实时错误作者对照的 [plan.json](experiments/20261102_live_validator_wrong_author/plan.json) 同时保留两套不同的负例作者字段；脚本实际使用 `replacement_first_author`，结果可按实际输入解释，但原计划存在歧义，不能声称负例由无歧义的预先冻结计划定义。文件哈希及自述时间也不构成独立时间戳证明。
- 本轮样本量小、非随机，未充分覆盖多来源错误合并、真实环境中的机构作者或细微姓名差异。原始测试方案中要求的人工核对材料及完整模型端到端流程不能由上述受控或分阶段结果替代；后者已按用户要求移出本轮范围。
- 拒卡自动修复／复核闭环仍不属于本任务；参见[后端待办](后端代码审查与待办清单.md#8-validator)。

## 原始任务基线（2026-11-01）

以下内容保留制定时的目标与当时现状，供追溯；“现有”“尚未”和未勾选复选框不代表 2026-11-02 的实际进度。

## 目标与职责

使文献元数据核验成为正常工作流中 Validator 真实性核验的组件，默认发挥作用。抽象层级为：

```text
Validator：真实性核验和最终放行决定
├── 本地材料、引文、位置及溯源检查
└── 文献身份核验
    └── 元数据服务层：查询、候选身份卡组装、来源／冲突／故障记录
        ├── DOI.org Provider
        ├── Crossref Provider
        └── DataCite Provider
```

元数据服务向 Validator 提供候选身份卡与查询事实；各 Provider 访问各自数据库，不作放行决定。后端入口负责服务的配置、创建和关闭。外部题录一致仅支持文献身份核对，不证明论文内容或结论真实，也不能绕过本地引文、位置及文件检查。

正常 Builder 输出一张 Evidence Card 对应一篇 Work，可包含这篇文献的多条引文；多个数据库来源可以为该 Work 提供身份候选。身份卡和 Evidence Card 是不同对象。

## 已有基础与目标差距

- 现有 Validator 支持显式注入元数据服务；正常工作流默认仍构造本地模式，生产入口尚未接入服务创建与生命周期。见 [Validator](../backend/src/novelty_agent_framework/agents/evidence_validator.py) 和[工作流](../backend/src/novelty_agent_framework/workflows/novelty.py)。
- 现有三个 Provider、统一检索及错误事件已具备基础能力，相关离线回归和公共 API 冒烟是历史记录，不等于本任务验收通过。见[既有验证记录](database-providers.md#验证)。
- 当前组装仅按相同 DOI 合并，无 DOI 记录独立保留；同 DOI 字段冲突留在同一卡中。当前比较规则和多候选处理与本任务下述目标不同，实施时须调整而不能把现状误写为已满足。见[组装实现](../backend/src/novelty_agent_framework/tools/metadata_retrieval.py)和[比较实现](../backend/src/novelty_agent_framework/core/metadata_verification.py)。
- Builder 正常路径能按 Work 拆分可安全归属的混合草稿，并拒绝无法安全归属的草稿；数据结构本身不强制所有入口的一卡一文。见 [Builder](../backend/src/novelty_agent_framework/tools/evidence_card_builder.py) 和[拆卡测试](../tests/test_evidence_card_builder.py)。

## 功能与验收条件

### 1. 正常入口和资源生命周期

- [ ] 正常后端工作流默认启用元数据核验；开关只向后端开发者暴露，不向前端用户暴露。
- [ ] 通过正常工作流入口启动时，能证明 Validator 调用元数据服务和 Provider，而不是仅在测试中手动替换 Validator。
- [ ] 工作流结束或异常退出时，正确关闭由工作流／服务创建并持有的服务及客户端；外部注入资源的所有权和关闭责任须明确并得到验证。
- [ ] 开关关闭时使用本地模式，并记录“元数据核验未执行：后端配置关闭”。

### 2. 一卡一文和身份候选

- [ ] Builder 的正常输出保持一卡一文；可安全归属的混合草稿按 Work 拆卡，无法安全归属时拒绝并记录具体原因。一张卡的多条引文须归属于同一 Work。
- [ ] 即使异常输入绕过 Builder，Validator 也不能将跨多个 Work 的卡误判为正常的一卡一文。
- [ ] 每篇待核验文献分别形成身份候选。相同 DOI 且无冲突的数据库记录可合并、互补字段，并保留字段值及来源；同 DOI 的记录出现字段冲突时保留独立候选及冲突记录，分别核验。
- [ ] 没有共同 DOI 时，只在有足够题录信息确认属于同一篇文献时合并。首版基础条件为标题、完整作者序列和出版年份均存在且一致；比较可忽略大小写与多余空白。信息不足或冲突时保留独立候选并记录原因。不能将不同 DOI 简单按题名合并。
- [ ] 本地 Work 没有 DOI，**或云端返回的记录均没有 DOI**时，启用额外题录字段核对。本地有 DOI、云端记录无 DOI 时，可按无共同 DOI 的题录规则判断文献身份，但须说明本地 DOI 未得到云端 DOI 对照。
- [ ] 双方都有 DOI 但不同，该候选记录 DOI 不一致并不通过；其他候选仍可继续核验。
- [ ] 没有可用的共同 DOI 且候选缺少标题、完整作者序列或年份之一时，记录具体缺失字段，该候选不能单独通过。
- [ ] 无 DOI 核对时，双方都有页码、页数等受检字段但不一致，记录具体值、来源及字段差异，该候选不通过；缺失字段与不一致分开记录。文件大小仅作辅助记录，不作为直接拦卡条件。
- [ ] 候选之间采用 **OR**：至少一张身份候选符合核验条件，即可放行该 Evidence Card；其他候选的不匹配及来源冲突仍可追溯。所有候选均不符合时不放行，保留各自具体原因。
- [ ] 元数据匹配不能使本地文件、引文或位置检查失败的卡通过。

### 3. 故障和降级

- [ ] 元数据服务初始化失败不终止工作流；记录具体启动故障，切换本地 Validator，并逐卡标记“元数据核验未执行：服务初始化失败”。本地校验通过的卡可进入 Reviewer，不能标为通过外部核验。
- [ ] 服务启动后，单个 Provider 故障而其他来源足以匹配时，该卡可通过；故障来源及具体原因仍被记录。
- [ ] 服务启动后，某卡所有可用来源均故障时，记录各来源具体故障，该卡不进入 Reviewer；其他卡及工作流继续处理，不将本次请求故障扩大为整次运行降级。
- [ ] 查询实际成功但返回候选未找到目标文献时，记录“当前元数据核验未找到该文献”，并限定查询及来源范围，不定性为文献虚构。查询未执行、超时、限流、服务故障等不能记录为已查询未找到；部分来源未找到、部分来源故障时同时保留两类事实。
- [ ] 按实际情况明确区分未找到、查询未执行、字段不足、字段不一致、候选冲突、超时、连接失败、限流、服务错误及不支持的查询；不以模糊的“无法核实”替代具体原因。

### 4. 输出与可追溯性

- [ ] 每张受检卡可查到是否执行、实际模式、来源及查询状态、候选与匹配结果、字段来源与冲突、具体失败原因及最终放行结果。
- [ ] 运行记录反映实际模式；本地降级或配置关闭不能表示为已完成外部核验。故障与相关 Card、Evidence、Work、Provider 和运行关联；已有错误事件与审计记录正确落盘。
- [ ] 验证 Reviewer 实际输入：拒卡不得进入，放行卡进入；本地降级时仅按本地校验结果处理并保留未执行外部核验的标识。

## 测试方案和通过标准

各层结果独立记录，不能用某一层的成功代替另一层。记录运行命令、代码版本、配置、测试数据与输出；固定场景全部符合预期后，离线功能验收才可通过。

1. **离线组件测试**：覆盖来源响应、无 DOI 和不同 DOI、字段缺失与冲突、同 DOI 冲突拆候选、字段溯源、候选 OR、无关候选、Provider 故障和具体错误分类；阻断真实网络及模型调用。
2. **正常入口集成测试**：通过实际入口，使用受控服务验证默认启用、后端关闭、初始化失败降级、运行中故障、服务资源关闭、逐卡审计与错误落盘、Reviewer 实际接收集合。覆盖 Builder 混合草稿拆卡和异常跨 Work 卡。
3. **代表性材料测试**：使用人工核对的材料集，包含正确文献、错误 DOI、无 DOI、同名候选、缺失字段、同 DOI 来源冲突、错误引文／位置，以及作者姓名、版本、日期、页码和页数差异。分别统计误通过和误拒绝，列明样本、原因与来源；先展示结果，再决定是否调整规则，不预设通过率。
4. **公共 API 验证**：使用少量固定样本验证真实响应、来源结果和故障记录，结果与离线测试分别报告；网络故障不能伪装为未找到。该项不调用外部模型，也不能替代正常入口集成测试。
5. **真实模型完整流程**：作为后续独立验收；实际运行前由用户决定。离线功能验收和公共 API 验证不得宣称已完成此项。

## 边界与后续事项

- 本任务不包含 Validator 拒卡回原任务的自动修复和复核闭环；该工作见[后端待办](后端代码审查与待办清单.md#8-validator)。

- 探针的一小时校园网记录不等于完整 24 小时或跨出口可用性验收，详见[探针记录](validator-doi-api-mainland-probe.md)。
- 本文档的整理不执行测试、公共 API 请求或外部模型调用；实施和各层验收结果须另行记录。
