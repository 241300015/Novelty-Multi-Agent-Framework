# Planner 双阶段重构实施与验收方案

本方案规定 Planner 概念阶段、策略阶段及其 Harness、Prompt、纠错、持久化和验收行为。Planner 以单个调研任务为规划单位，只交付该任务语言的通过内容；模型负责内容生成和语义判断，Harness 负责流程、合法选项、预算、确定性检查及结果组装。

本轮仅整理实施方案，不代表已经完成代码改造或实验验收。default 报告模板展示作为后续工作，本次先完成可供其读取的持久化文件与索引。

## 一、目标与范围

本分支的实施目标包括：

1. 概念阶段：依据上游查新点和当前任务生成概念，完成复核、局部纠错与部分放行。
2. 策略阶段：依据通过的任务语言概念，按 strict、medium、broad 顺序逐档生成策略，完成复核、纠错与部分放行。
3. 同步调整 Prompt 与 Harness，使模型只处理当前阶段的内容任务，由程序控制阶段推进、预算和交付。
4. 使用离线测试及真实模型定点实验验收 Planner，不要求完成整个查新工作流。
5. 保存必要的运行、问题、修复和放行记录，建立持久化文件与索引，供后续完整 default 报告查询。

Planner 以上游提供的查新点为依据，不判断查新点是否完整覆盖论文，不承担 Extractor 的质检门控，不新增论文原文读取，也不修改上游查新点。

任务所需语言表述缺失时，Planner 可以依据另一语言查新点补译或整理检索词项；生成词项仍须检查概念归属和技术含义，防止补译漂移。

## 二、规划粒度与语言规则

### 2.1 一个 task 对应一次独立规划

沿用现有任务结构：每个 `ResearchTask` 绑定一个查新点和一种检索语言。`task_type` 表示调研类型，`language` 表示检索语言，任务描述提供必要的任务要求。

`coordinator.plan` 已支持按启用语言分别创建任务。启用中文和英文时，同一个查新点对应两个独立 task，而不是一个双语 task。两者分别规划、分别复核、分别维护预算和通过集，只交付各自语言的策略。

task 标识须结合查新点和运行使用；不能仅凭 `task_id` 合并记录。规划尝试也须可区分，避免重跑、补检或复验覆盖原始记录。

### 2.2 查新点语言由 Harness 判断

Harness 根据 `claim` 和 `claim_en` 是否非空确定可用语言，不从论文语言推断，不让模型决定是否进入跨语言对照流程。

调整现有输入约束：允许 `claim` 或 `claim_en` 其中一项为空，但两者至少有一项包含非空白内容。判空不改变上游原始内容；两个字段都为空的输入在模型调用前拒绝，并记录输入问题。

| 查新点可用表述 | 当前 task | 概念阶段行为 |
| --- | --- | --- |
| 只有中文 | 中文 | 生成中文概念，对照中文查新点复核，不生成英文对照概念 |
| 只有中文 | 英文 | 生成英文任务概念和中文对照概念，检查补译漂移 |
| 只有英文 | 英文 | 生成英文概念，对照英文查新点复核，不生成中文对照概念 |
| 只有英文 | 中文 | 生成中文任务概念和英文对照概念，检查补译漂移 |
| 中英文均有 | 中文 | 使用同侧中文表述生成和复核中文概念，不做跨语言对照 |
| 中英文均有 | 英文 | 使用同侧英文表述生成和复核英文概念，不做跨语言对照 |

规则是：**有同侧查新点表述则不对照，只有对侧查新点表述才对照。概念复核始终存在。**

### 2.3 任务概念与对照概念

任务概念是当前 task 语言的候选概念；只有这些概念能够进入当前规划的通过集。

对照概念是在需要补译时使用的来源语言参考，用于辅助判断概念归属和技术含义是否漂移。对照概念不建立另一语言的通过集，不作为可交付成果，不共享到另一 task。

原始查新点始终是判断依据。对照概念不是标准答案，不能因为它提取有误而迫使正确的任务概念向错误参考靠拢。生成与复核的最终目标都是形成符合要求的检索策略。

跨语言比较不要求概念数量、顺序或措辞机械一致。只要任务语言概念尚未得到明确通过结论，就不能因对照材料存在或形式一致而放行。

## 三、Harness 与模型职责

### 3.1 Harness 职责

Harness 负责：

- 校验输入绑定，判断语言条件，推进当前阶段和策略档位。
- 发放当前合法候选与选项，维护概念、问题、策略及调用的标识和绑定。
- 管理任务语言概念通过集、错误集、策略通过集及未解决问题。
- 管理阶段输出契约纠错、概念纠错、各档策略纠错和环境重试预算。
- 执行 schema、引用、表达式语法及资源上限等确定性检查。
- 裁剪 schema 明确禁止的多余字段，重新验证并记录。
- 校验模型构造的逻辑表达式，展开概念词项，判定实际表达式是否完全重复。
- 持久化过程与结果，仅组装已复核并接受的正式成果。

### 3.2 模型职责与输出契约

遵循“能选就不写”：程序已有可靠候选时，模型从候选中选择；没有现成候选时，模型生成必要内容。

模型负责概念术语、分类、别名等语义内容，策略所选概念、逻辑连接及必要的策略意图，以及生成结果的语义复核。身份、底层绑定、流程状态和预算由 Harness 维护。

策略模型可自由组合已通过概念与允许的逻辑符号。它不需要生成新的概念标识，也不能用策略阶段绕过概念审核、引入未通过概念或新词项。

### 3.3 Prompt 调整

概念生成、首次概念复核、局部概念纠错、局部概念复核、策略生成、策略纠错、策略复核和重复策略判断，都只提供当前操作所需的任务、查新点、候选与输出契约。

生成与复核使用独立上下文。复核模型不继承生成对话；局部复核也不继承纠错过程对话。必要的待检内容和查新点依据由 Harness 显式传入。

Prompt 不要求模型选择下一阶段、维护预算、重写通过集，或补全程序可确定的机械字段。运行时实际 schema、合法选项和限制须与 Prompt 一致。

## 四、第一阶段：概念生成、复核与纠错

### 4.1 首次生成与整体复核

1. Harness 判断任务语言与查新点语言，确定是否需要补译对照。
2. 生成任务语言概念；仅在需要跨语言补译时生成对照概念。
3. 先恢复合法、可检查的结构。整份结果不能解析或存在缺失、类型错误时，按概念阶段整体输出契约预算处理。
4. 使用新上下文进行首次复核，接收查新点、必要任务信息、待检任务概念及必要对照材料。
5. 复核检查核心概念覆盖、分类、词项与别名归属、技术含义，以及需要补译时的跨语言一致性。
6. Harness 根据明确的复核结论建立通过集和错误集；复核指出的核心概念遗漏作为独立问题登记。

首次整体复核承担概念之间的分类、归属和整体覆盖检查。未复核、复核缺失或无法明确判定的候选不进入通过集。

### 4.2 局部纠错与复核

首次复核后，整个概念错误集最多推进三轮纠错。首次生成和首次复核不计入这三轮。

每轮按以下方式处理：

1. 逐概念提供具体问题，执行局部纠错；遗漏问题生成独立的补充概念。
2. 对每个修正或补充的概念，单独使用新上下文复核。
3. 局部复核只接收查新点、必要任务信息、当前待检概念及必要补译对照材料。
4. 已通过且未修改的概念保持不变，不出现在后续局部纠错和局部复核输入中。
5. 通过项移入通过集；未通过项保留问题、理由和修复轨迹，进入下一轮。

修复 B 时不带入已通过的 A，也不借局部复核重新审查 A。不得在每轮末尾重新复核全部通过概念，导致已经结束的问题反复打开。

补充的遗漏概念只复核该概念，不重新复核已通过集。纠错轮次属于整个错误集，不因某项晚加入而重新获得三轮。

### 4.3 阶段结束与部分放行

- 错误集提前清空时，进入策略阶段。
- 三轮后登记剩余错误，只使用通过的任务语言概念继续。
- 任务语言通过集非空时，可以进入策略阶段；不要求全部候选通过。
- 任务语言通过集为空时，当前 task 不能进入策略阶段。对照概念不能替代通过集。
- 若模型不可调用或运行级调用预算耗尽，按故障停止规则处理；不能仅因尚有语义纠错轮次而继续调用。

## 五、第二阶段：逐档生成与复核策略

### 5.1 档位推进

Harness 按 `strict → medium → broad` 顺序推进。每档输入包含：

- 当前档位、任务要求及必要查新点信息。
- 当前 task 的通过概念目录。
- 最近一档已通过策略；此前没有通过策略时，明确告知没有可参考的上一档。
- 当前合法表达式契约和必要纠错反馈。

模型自主选择当前策略所需概念、逻辑组合和放宽方式。每档不要求使用所有通过概念，也不要求各档概念集合机械嵌套。

Harness 校验并展开表达式后，新上下文复核模型检查概念使用是否正确、是否保留相关核心机制、是否符合当前档位意图，以及相对最近通过策略的调整是否合理。

只有通过的策略可作为后续档位参考。当前档纠错不能修改上一档。某档最终失败后登记原因并尝试下一档；例如 strict 失败且没有任何通过策略时，medium 在“无上一档通过策略”的条件下生成。

每个 task 的每个档位各有三轮语义纠错预算，首次生成与首次复核不计入三轮。因 task 为单语言，预算不跨语言任务共享。

### 5.2 模型构造表达式与 Harness 基本约束

模型负责选择并拼接表达式，支持以下元素：

- Harness 发放的已通过概念编号。
- `AND`、`OR`。
- 用于分组的括号。

例如：`C1 AND (C2 OR C3)`。本次不新增概念级 `NOT`；已有词项排除设置与概念级逻辑运算须区分。

Harness 检查：

1. 表达式非空，引用均来自当前通过概念目录。
2. 两个操作数之间有合法逻辑符号，运算符两侧有完整操作数。
3. 括号平衡，分组和运算符顺序合法，表达式完整。
4. 表达式使用受限、有限的语法；长度、节点数和嵌套深度有明确上限。
5. 概念展开使用已通过的词项及实际生效的别名、排除设置，不补造内容。

具体资源上限在实现时配置并记录，覆盖边界测试。Harness 不通过强制锚点、强制删除概念、固定 broad 只剩一个概念等方式替模型作语义决策，也不把 OR 表达式重写成 AND。

语法合法不等于语义通过；通过确定性校验的策略仍须新上下文语义复核。

### 5.3 重复策略

重复以概念展开后的实际检索表达式为准，包含生效的词项、别名与排除设置。不能仅比较 `C1 AND C2` 这类概念编号字符串。

Harness 只捕获规范化后完全相同的实际表达式，不进行同义词推断或语义等价推断。规范化规则须确定、可测试，并保留原始与规范化表达式供追溯。

捕获重复后，交复核模型作“放行／不放行”的二元选择：

- 放行：满足当前档语义复核要求后，当前档按通过处理。
- 不放行：进入当前档纠错。

重复判断不替代原有的每档语义复核。不同表达式是否语义等价，以及这样的策略是否适合当前档位，由复核模型判断。

### 5.4 策略交付

至少一档策略通过即可交付该 task 的通过策略集。失败档位不进入正式结果，也不生成占位策略。

没有任何策略通过时，当前 task 规划失败。已经通过的概念仍保留在审计记录中，但不能伪装成可交付检索计划。

正式 `SearchPlan` 只包含当前 task 的通过概念和通过策略。普通检索计划必须同时包含三档的旧契约须调整，相关编译和消费代码不能再假设三档一定存在。

## 六、预算与故障处理

### 6.1 预算作用域

| 预算 | 作用域 | 上限与计数 |
| --- | --- | --- |
| 概念整体输出契约纠错 | 一次 task 规划的概念阶段 | 最多三轮模型修复 |
| 策略整体输出契约纠错 | 一次 task 规划的策略阶段，跨档共享 | 最多三轮模型修复 |
| 概念语义纠错 | 当前 task 的整个概念错误集 | 首次复核后最多三轮 |
| 策略语义纠错 | 当前 task 的每个档位 | 每档首次复核后最多三轮 |
| 环境重试 | 一次逻辑模型调用 | 首次失败后最多再重试三次 |
| 运行级模型调用预算 | 当前执行环境配置的运行范围 | 所有实际调用按运行配置计数，触顶停止 |

阶段整体契约预算不能因换概念、换操作或换档位而重新发放。语义纠错轮次、契约修复次数与实际模型调用次数分别记录，不用单一 `max_attempts` 混合代替。

### 6.2 整体输出契约纠错

需要模型参与修复的集合级输出错误，包括整份结果无法解析、必需字段缺失或类型错误。

整份概念结果无法解析时，先恢复可比较结构，再开展概念复核；不消耗概念错误集的三轮语义纠错预算。策略阶段的整体输出契约预算与各档语义纠错预算分开计算。

每次修复均须记录错误类别、修复对象、所使用预算及剩余额度。实现时为确定性检查与模型输出错误建立明确的分类映射，避免同一错误被不同路径计入不同预算，或借类别切换获得无限修复。

### 6.3 自动裁剪

对当前 schema 明确不允许的多余字段，Harness 可直接裁剪，记录字段路径与裁剪内容，随后重新验证，不消耗模型纠错预算。

缺失字段、类型错误及其他不能确定修复方式的问题交模型处理。程序不猜测或补造概念、策略及语义字段值。机械身份和绑定仍由 Harness 按自身契约填写。

### 6.4 环境故障与终止

连接中断、超时等适合重试的环境性故障使用独立预算：首次失败后最多再重试三次。环境重试期间不立即消耗纠错轮次。

三次重试后仍失败，对当前 Planner 规划默认视为模型不可调用：记录具体原因，若正在执行纠错则登记当次纠错失败及轮次消耗，停止该次规划的后续模型调用。首次生成或首次复核遇到此情况时，记录相应初始调用失败，不虚构已执行的纠错轮次。

明确不可恢复的服务、凭据或配置错误，以及运行级调用预算耗尽，同样停止新调用。模型成功返回但输出不合法属于模型输出错误，不使用环境重试预算。

终止时保留同一次规划中已经检查并由 Harness 接受的可用成果。已有通过策略时交付通过策略集；只有通过概念而没有通过策略时，保存概念审计成果并记录规划失败。未检查内容不算通过。

## 七、持久化、索引与报告边界

### 7.1 目录结构

在当前运行的产物根目录下保存：

```text
planner/
  index.json
  <planning-attempt-key>/
    input.json
    events.jsonl
    summary.json
    plan.json                 # 仅存在通过策略时生成
    calls/
      <call-id>.request.json
      <call-id>.response.json
```

目录键由 Harness 分配，并在索引中绑定运行、查新点、task 和规划尝试；不得把未校验的模型文本直接用作路径。

| 文件 | 内容与用途 |
| --- | --- |
| `planner/index.json` | 按运行、查新点、task 和规划尝试定位记录，保存状态、产物路径及内容摘要 |
| `input.json` | 当前任务实际使用的查新点、task、语言判断、配置和版本信息等输入快照 |
| `events.jsonl` | 顺序记录生成、裁剪、复核、问题登记、修复、预算变化、失败及放行事件 |
| `summary.json` | 当前及最终状态、通过项、未解决问题、失败原因、预算汇总和对应事件编号 |
| `plan.json` | 仅含通过内容的正式 `SearchPlan` |
| `calls/` | 各次模型输入输出及可关联的调用错误；事件引用对应调用 |

调用记录保存模型实际收到和返回的内容，不保存鉴权凭据。没有响应的失败调用保存错误与缺失响应原因，不伪造响应。

### 7.2 追溯与完整性

记录必须能够追溯：输入版本、问题来源、受影响概念或档位、修复前后内容、复核输入输出、预算使用、失败原因和最终放行情况。

必要审计记录不依赖 debug 开关。失败或部分成功的规划同样要有索引、事件和摘要；没有通过策略时，不制造空的正式计划。

索引须区分进行中、已结束和失败等状态。文件内容摘要与状态保持一致，终态产物可校验；重跑和复验不得覆盖原记录。读取时检查运行绑定、路径、文件存在性和内容摘要，避免把其他 task、旧运行或其他场景的记录混入当前结果。

### 7.3 报告边界

未通过概念和策略不进入正式 Planner 结果，不交给下游作为通过内容，不出现在普通查新报告中。

这些内容及其问题、纠错和复核轨迹保存在审计文件中。本次验收要求能够通过索引找到并验证必要记录；后续再将这套文件与索引接入完整 default 报告的输入登记和模板展示。

本次不要求完成 default 模板渲染，不为了生成完整报告执行整个查新流程，也不向真实实验产物补造证据或最终报告。

## 九、离线验收

相关控制流程测试须全部通过，至少覆盖以下项目：

| 验收方向 | 必测行为 |
| --- | --- |
| 输入与语言 | 中英文至少一项非空；同侧优先；仅对侧时才补译对照；双语查新点下的两个 task 独立执行 |
| 首次复核 | 同语言也必须复核；检查覆盖、分类和归属；跨语言不机械匹配数量或顺序 |
| 新上下文 | 首次复核不继承生成对话；局部复核不继承纠错对话 |
| 局部隔离 | 已通过 A 不出现在 B 的局部纠错、复核输入中；通过 A 的内容不被修改 |
| 遗漏补充 | 核心遗漏单独登记、补充并局部复核；不重开整个通过集 |
| 对照边界 | 对照概念不进入通过集，不作为另一语言成果；不能替代为空的任务语言通过集 |
| 放行 | 未复核内容不得进入正式结果；部分概念通过可继续；空通过集停止 |
| 预算 | 首次生成和复核不计语义纠错；各类预算独立且不重置；错误集最多三轮，每档最多三轮 |
| 环境故障 | 首次失败后最多三次重试；触顶后不再调用；成功返回但格式错误不走环境重试 |
| 契约修复 | 整体无法解析先修契约；缺失与类型错误不由程序猜测补值 |
| 自动裁剪 | 只删除明确禁止的字段，记录内容，重新验证，不扣模型纠错预算 |
| 策略推进 | 严到宽、跳过失败档、传递最近通过档、当前纠错不修改前档 |
| 表达式 | AND、OR、括号、引用验证、缺连接符、资源上限；不得把模型逻辑改写成固定模板 |
| 重复 | 按实际表达式比较；二元放行决定不替代语义复核；不同词项设置不被仅凭编号误判 |
| 部分策略 | 一档通过可交付；没有通过策略则失败；缺失档位无占位产物 |
| 成果保留 | 契约或调用预算耗尽时只保留先前接受内容，不放行未检查草稿 |
| 持久化 | 成功、部分成功、失败均可定位；索引绑定及摘要正确；debug 关闭仍有必要审计 |
| 产物隔离 | 正式计划不含失败内容；不同 task、场景、原始运行和复验不串用数据 |
| 注入驱动 | 注入位置正确；保存前后版本；复核模型看不到注入答案或原始未注入草稿 |

纠错机制验收不能只证明发生了调用或最终停止。必须验证错误被准确定位、修复输入正确、修改针对问题、修改后进行了独立复核，且最终放行与复核结论一致。

## 十、真实模型实验

### 10.1 样本与人工核心概念清单

使用两篇不同领域的历史查新点文件，各固定一个查新点作为首批样本：

- [MF2033k6lC 图神经网络相关历史查新点](experiments/20260915_224229/run/MF2033k6lC/novelty-points.json)。
- [MG19333vrw 音乐生成与注意力机制历史查新点](experiments/20260917_005448/runs/full/0002/MG19333vrw-debug-full-20260907/novelty-points.json)。

两份文件都包含多个查新点。实验前固定具体 `point_id`、原始输入摘要及选用理由；文件标题或链接位置不能替代样本标识。依据所选查新点人工整理并冻结核心概念清单，不以此验收 Extractor 是否完整覆盖论文。

记录模型、模型参数、Prompt 和代码版本、实际配置与预算，以便对比原始运行和复验。不同运行使用独立上下文，不沿用前次生成或复核历史。

### 10.2 自然实验矩阵

每个查新点执行四种场景，每种独立运行三次：

| 场景 | 提供给 Planner 的查新点 | task | 概念对照 | 每次场景的 Planner 调用数 |
| --- | --- | --- | --- | --- |
| A | 仅中文 | 中文 task | 不对照 | 1 |
| B | 仅中文 | 英文 task | 对照，检查补译 | 1 |
| C | 仅英文 | 中文 task | 对照，检查补译 | 1 |
| D | 中英文均有 | 中文、英文两个独立 task | 两者各有同侧表述，均不跨语言对照 | 2 |

总计 **24 个自然场景、30 次独立 Planner task 规划**：`2 × 4 × 3 = 24`，`2 × (1 + 1 + 1 + 2) × 3 = 30`。

模拟单语言输入时，在实验输入副本中隐藏另一语言的 claim 和相应技术特征，不把隐藏内容通过其他上下文字段泄漏给模型；原始历史文件保留不变。该操作只模拟输入条件，不代表论文只有一种语言。

双语场景按两个独立 task 统计调用、预算、通过概念与策略；不能以一个 task 的成功抵消另一个 task 的失败。

### 10.3 可控错误实验

另准备两类可控错误，每类独立运行三次，共六次注入实验，单独统计，不计入自然错误发生率：

1. 遗漏核心概念。
2. 别名归属错误。

注入位置固定在首次概念生成完成、首次复核之前：

- 遗漏实验删除指定核心概念。
- 错配实验把指定别名移动到不属于它的概念。
- 保留注入前后完整版本、修改位置、注入类型和预期检测目标。
- 复核模型只看到修改后的待检查结果，不看到注入说明、预设答案或原始未注入草稿。
- 注入后进入正常 Harness 检测、修复、新上下文复核、预算和放行流程，不直接构造错误集替代检测。

实验前在清单中固定注入所用样本、task、目标概念或别名。若当次生成没有所需注入对象，记录该次不具备注入条件，不把未实施的注入当成成功测试，也不悄悄切换错误类型。

分别统计检测是否正确、修改是否针对问题、复核是否合理、问题是否解决、未解决时是否按规则终止及处理通过集。不能用“有修复调用”代替纠错有效性的判断。

## 十一、人工检查、结果分类与复验

### 11.1 人工检查

依据冻结的核心概念清单，逐次记录：

- 任务语言概念是否忠实于查新点。
- 词项和别名归属是否正确，核心概念是否覆盖。
- 发生补译时，技术含义是否一致，是否存在漂移。
- 策略概念使用、核心机制保留和逐档放宽是否合理。
- 局部纠错、复核、预算、记录和放行机制是否按要求执行。
- 部分结果是否足以形成有意义的检索计划。

每项判断保留理由或记录引用。语义判断无法确认时标为待核实，不计入通过。不要求每档使用所有通过概念。

### 11.2 结果分类

| 结果 | 判定 |
| --- | --- |
| 完整达标 | 核心概念覆盖及人工语义检查通过；三档策略均通过且人工检查合格 |
| 符合预期的部分结果 | 虽有概念或档位未通过，但人工确认检测、纠错、复核、预算、记录和放行均按预期；放行内容无明显语义错误，足以形成有意义的检索计划 |
| 未达标／待核实 | 存在错误放行、机制未按预期执行、内容不足以形成有意义计划，或关键语义判断尚未确认 |

单语场景按该 task 判定；双语场景只有两个 task 均完整达标才属于完整达标。两个 task 均达到完整达标或人工确认的部分结果、且至少一个为部分结果时，场景归为部分结果；任一 task 未达标或待核实，则场景不得计入验收通过。

### 11.3 整批通过条件

1. 相关离线控制流程测试全部通过。
2. 24 个自然场景中的 30 次 task 规划全部达到完整达标，或经人工确认的符合预期的部分结果。
3. 可控遗漏和别名错配按设计被检测和处理；未修复问题也按规则记录并隔离。
4. 文件与索引能够定位输入、问题、修复、复核、预算和最终结果，并通过绑定及内容摘要校验。
5. 正式结果不含未通过、未复核内容；原始运行、注入实验与复验结果明确区分。

完整 default 报告模板渲染不属于本批通过条件，后续接入时另行验证。

### 11.4 失败修复与复验

失败修复后至少复验受影响场景及相关控制路径。修改共享 Harness、预算、复核协议或表达式处理时，扩大到所有受影响场景。

保留修复前后记录和版本信息，区分原始运行与复验，不覆盖或只保留成功结果。整批结论说明哪些原始场景失败、进行了什么修改，以及复验覆盖和结果。

## 十二、实验监视与暂停

真实实验进行时委派只读 Agent 监视：场景进度、调用次数与预算、错误登记、纠错和复核推进、产物完整性、通过集及策略档位分布。

监视 Agent 只读取和报告观察，不修改代码或实验数据，不自行调用模型。主 Agent 核查异常并决定暂停或处理。

出现以下情况时暂停后续实验：

- 未通过或未复核内容进入正式 Planner 结果。
- 预算或调用失控、疑似循环，或明显超出预期。
- 使用错误的查新点、task、语言或其他场景的数据。
- 必要记录、索引或产物缺失，无法判断实际过程。
- 服务、凭据或配置持续不可用，继续执行只会重复失败。

单个概念或档位在规定纠错后仍失败，只要记录和放行正确，不自动中断整批实验；保留为待人工判定的部分结果。暂停期间保留已有产物、异常原因和处理记录，修复后按受影响范围复验。
